# XpiX — студия вайбкодинга

## Проекты студии

- [Apple IQ](https://reformoti.github.io/AppleIQ/) — браузерная игра.
- [Глибоке Поле](https://reformoti.github.io/XpiX/gliboke-pole/) — полноэкранная 3D-лаборатория на Three.js. Её **интерактивная звезда теперь работает прямо в первом экране XpiX**: её можно вращать, менять цвет и силу свечения. На главной и в полном режиме используется общий модуль `gliboke-pole/star-geometry.js`.

Главная страница сохраняет существующие разделы и Apple IQ. `web/deep-field-preview.js` отвечает за встроенную сцену, при отсутствии WebGL показывается прежняя SVG-графика. `npm run build:pages` переносит нужные файлы в корень и `docs/`, а `npm run build` готовит статические ресурсы для Worker. При сниженной анимации или если блок не виден, непрерывный рендеринг останавливается.

## Версия для GitHub Pages

Главная страница `index.html` и её ресурсы размещены в корне репозитория, чтобы GitHub Pages показывал сайт XpiX вместо README. Папка `docs/` содержит ту же статическую версию с прежним дизайном, портфолио Apple IQ и скрытым номером телефона. Сборка не требует установки зависимостей.

Для публикации откройте **Settings → Pages** и выберите **Deploy from a branch → main → /(root) → Save** (публикация из `/docs` также поддерживается). После окончания публикации GitHub покажет адрес сайта в этом разделе.

Для обновлений редактируйте `web/`, затем выполните `npm run build:pages` и загрузите изменённые исходники, файлы сайта из корня и `docs/` в GitHub. Сборка обновляет оба варианта публикации. Относительные пути позволяют работать и в `/XpiX/`, и на собственном домене.

**Оплата на GitHub Pages выключена:** статическая версия не обращается к несуществующему API, не принимает деньги и не открывает номер. Полный телефон и ключи оплаты не копируются в `docs/`. Для платного открытия понадобится подключённый серверный обработчик. Исходная реализация Worker сохранена ниже.

```sh
npm run build:pages
```

## Запуск

Node.js 22 или новее. Зависимости устанавливать не нужно.

```sh
npm run dev
```

Откройте `http://localhost:3000`. Для изменения порта задайте `PORT`.

```sh
npm test
npm run build
npm run validate
```

`web/` — HTML, CSS, JS и SVG. `worker/index.js` — серверные маршруты. `scripts/build.mjs` встраивает веб-ресурсы в самостоятельный Cloudflare Worker `dist/server/index.js`. GitHub Pages обслуживает подготовленную папку `docs/`. Серверный Worker или включённый Node-сервер нужен для защищённого платного открытия номера.

## Оплата: подготовлена, но выключена

Реальная оплата **не активирована**. Кнопка объясняет посетителю, что приём платежей ещё не подключён; деньги не списываются. Полный номер отсутствует в репозитории, HTML, JS и публичных ответах до оплаты. Сайт не открывает номер по нажатию «я оплатил», параметру URL или записи в localStorage.

Подготовлена интеграция LiqPay Checkout API v7. Для активации владелец должен подключить и активировать свой магазин LiqPay, настроить зачисление на свой счёт/карту в кабинете провайдера и добавить серверные переменные:

| Переменная | Назначение |
| --- | --- |
| `CONTACT_PHONE` | Полный телефон в международном формате, только серверный секрет |
| `SESSION_SECRET` | Случайный секрет от 32 символов, только сервер |
| `LIQPAY_PUBLIC_KEY` | Ключ активированного магазина |
| `LIQPAY_PRIVATE_KEY` | Приватный ключ магазина, только серверный секрет |
| `PUBLIC_ORIGIN` | Точный HTTPS origin сайта без пути |
| `PAYMENTS_ENABLED` | `true` только после активации магазина и проверки платежа на $0.15 USD |

Номер карты не нужен в исходном коде. Приватные ключи не публикуйте в GitHub и не размещайте в HTML. Используйте секреты хостинга; для локальной разработки скопируйте `.env.example` в `.env` (исключён из Git).

Сначала проверьте, что ваш активированный магазин принимает разовые платежи **0.15 USD**, и проверьте применимые условия/комиссии в кабинете LiqPay. Денежные операции при разработке не выполнялись. Live-проверка эквайринга требует аккаунта владельца; автоматические тесты используют имитацию ответов провайдера.

### Как открывается номер

1. Сервер создаёт заказ с фиксированной суммой 0.15 USD и подписывает параметры LiqPay с SHA3-256.
2. Подписанный HMAC-SHA256 идентификатор заказа хранится в cookie `HttpOnly`, `SameSite=Lax`, `Secure` на HTTPS. Доступ привязан к этому браузеру на 30 дней; cookie не содержит телефон.
3. Пользователь оплачивает на странице LiqPay и возвращается на сайт. Прямые карточные реквизиты сайт не получает.
4. Сервер запрашивает статус заказа непосредственно у LiqPay и сверяет магазин, ID, сумму, валюту, тип операции и успешный статус (`success` или `wait_compensation`). Тестовые, неподтверждённые и возвращённые платежи не открывают номер.
5. Полный телефон возвращается только после проверки. Ответы контакта и оплаты имеют `Cache-Control: no-store, private`. При сбое провайдера номер остаётся закрытым; посетитель может повторить проверку без повторной оплаты.

Подтверждение осуществляется через server-to-server Status API, поэтому webhook и база заказов не требуются. После очистки cookies или на другом устройстве автоматического восстановления доступа нет: сохраните открытый номер. Ссылка результата оплаты сама по себе доступа не даёт. Повторная попытка Checkout в течение 23 часов использует тот же заказ.

## Публикация исходной серверной версии

`.openai/hosting.json` хранит ID сайта, без секретов. Публикуемый архив содержит manifest и `dist/server/index.js`. Веб-сервер нужен для `/api/config`, `/api/checkout` и `/api/contact`. Публикация через Sites настроена в этом проекте; GitHub хранит исходный код. Изменения GitHub сами по себе не запускают новую публикацию Sites.
